# Аналитические витрины социальной сети на PySpark и HDFS

Учебный проект пакетной обработки событий: сообщения, реакции и подписки преобразуются в три витрины - пользователей, географических зон и кандидатов для рекомендации друзей. Географические признаки рассчитываются по координатам сообщений и справочнику городов.

**Стек:** Python, PySpark DataFrame API, HDFS, YARN, Apache Airflow, Parquet, NumPy.

Репозиторий рассчитан на подготовленное учебное Hadoop-окружение: самостоятельного Docker compose, исходных данных и сценария создания кластера здесь нет.

## Поток данных


Каждый скрипт получает каталог событий, путь к справочнику и каталог результата. Он читает всю доступную историю по переданному пути и записывает результат в режиме `overwrite`. **В рамках курса использовался срез данных за полгода. Поэтому параметризации по объему обрабатываемых данных реализовано не было** 

Для геопривязки используется сферическое расстояние по формуле гаверсинусов с радиусом Земли 6371 км. Событие сопоставляется со всеми городами через `crossJoin`; оконная функция выбирает ближайший город. **Такая реализация допустима, т.к. всего городов в справочнике с их координатами было около 25**

## Реализованные витрины

### 1. Пользователи - `datamart_users.py`

Обрабатываются отправленные сообщения. Время сообщения выбирается как `coalesce(event.datetime, event.message_ts)`, т.к. существуют отдельно события отправки сообщения в ЛС и в канал, у которых поля даты отправки сообщения отличаются. Ближайший город определяется для каждого `message_id`; затем события пользователя упорядочиваются по времени.

| Поле результата | Определение в коде |
|---|---|
| `user_id` | Отправитель сообщения. |
| `act_city` | Город последнего сообщения пользователя в прочитанной истории. |
| `home_city` | Последний город, где пользователь задерживался на 27 дней и более. |
| `travel_count` | Число переездов из одного города в другой (города могут повторяться). Считается по координатам сообщения |
| `travel_array` | Упорядоченная последовательность посещенных городов (города могут повторяться). Считается по координатам сообщения. |
| `local_time` | Время последнего сообщения, переведенное из UTC в часовой пояс его города. |

Город пребывания меняется, когда город очередного сообщения отличается от предыдущего. Например, последовательность `A, A, B, B, A` дает `travel_count = 3` и `travel_array = [A, B, A]`.

Порог для `home_city` измеряет разницу календарных дат первого и последнего сообщений сегмента (непрерывной последовательности одинаковых городов упорядоченной по дате сообщения). Он не доказывает непрерывное физическое проживание 27 дней и не требует сообщения каждый день. `act_city` также означает последнюю наблюдаемую точку, а не текущую геолокацию человека.

### 2. Географические зоны - `datamart_zones.py`

Витрина содержит недельные и месячные счетчики по зонам. Код формирует календарные ключи между минимальным и максимальным значениями входного поля `date`, соединяет их со всеми городами и дополняет отсутствующие числовые значения нулями.

| Поля результата | Смысл |
|---|---|
| `month` | Полное название месяца: `date_format(..., 'MMMM')`; год в ключ не входит. |
| `week` | Номер недели внутри месяца; границы выровнены по понедельникам, первая неполная неделя имеет номер 1. Это не ISO-номер недели года. |
| `zone_id` | `id` ближайшего города из справочника. |
| `week_message`, `month_message` | Счетчики сообщений. |
| `week_reaction`, `month_reaction` | Счетчики реакций. |
| `week_subscription`, `month_subscription` | Счетчики подписок. |
| `week_user`, `month_user` | Счетчики первых отправленных сообщений пользователей. Это не события регистрации. |

Правила расчета:

- Сообщение относится к ближайшему городу по собственным координатам и периоду `event.message_ts`.
- Реакция и подписка получают координаты **последнего сообщения автора во всей прочитанной истории**, а период берется из `event.datetime` соответствующего события.
- При выборе ближайшего города ключ сообщения - `message_id`, реакции - `(reaction_message_id, reaction_from)`, подписки - `(subscription_channel, subscription_from)`. Повторы одной такой пары не считаются отдельными событиями.
- Сообщения, реакции и подписки проходят `dropna()` по выбранным для них полям; авторы без подходящего сообщения не участвуют в геопривязке реакций и подписок.

**Т.к. срез данных берется за полгода, данный составной первичный ключ имеет смысл. В ином случае необходимо ввести разбиение еще и по годам.**

### 3. Рекомендации друзей - `datamart_friends_recommendations.py`

Витрина формирует кандидатов на взаимное добавление в друзья:

1. Найти пользователей с общей записью подписки на канал; пары упорядочить условием `user_left < user_right` и удалить повторы.
2. Исключить пары с перепиской в прочитанных событиях через `leftanti` join; направления сообщений нормализуются через `least`/`greatest`.
3. Определить координаты каждого пользователя по последнему отправленному сообщению, упорядоченному по `event.message_ts`.
4. Оставить пары с расстоянием не более 1 км.
5. Рассчитать среднюю точку координат пары и выбрать ближайший к ней город; добавить время обработки и его локальное представление.

| Поле результата | Смысл |
|---|---|
| `user_left`, `user_right` | Уникальная пара пользователей, записанная в упорядоченном виде. |
| `processed_dttm` | Время формирования результата через `current_timestamp()`. |
| `zone_id` | Ближайший город к средней точке координат пары. |
| `local_time` | Время обработки, переведенное в часовой пояс выбранного города. |

Близость определяется по последним сообщениям, без ограничения их давности. Здесь `local_time` относится к обработке, а в пользовательской витрине - к сообщению.

## Структура проекта

```text
src/
├── scripts/
│   ├── geo.py
│   ├── datamart_users.py
│   ├── datamart_zones.py
│   └── datamart_friends_recommendations.py
└── dags/
    ├── load_datamart_users_dag.py
    ├── load_datamart_zones_dag.py
    └── load_datamart_friends_recommendations_dag.py
```

`geo.py` читает справочник с явной схемой и приводит координаты к `DecimalType(7, 4)`, заменяя десятичную запятую точкой. Остальные скрипты запускаются отдельно и не зависят от результатов друг друга.

## Входные данные

События - Parquet, партицированные по дате, с полями `event_type`, `lat`, `lon` и вложенной структурой `event`. 

| Тип события | Поля структуры `event`, используемые скриптами |
|---|---|
| `message` | `message_id`, `message_from`, `message_to`, `message_ts`, `datetime`. |
| `reaction` | `reaction_from`, `message_id`, `datetime`. |
| `subscription` | `user`, `subscription_channel`, `datetime`. |



Справочник городов - CSV с заголовком и разделителем `;`. Ожидаются колонки в таком порядке:

```text
id;city;geo_lat;geo_lon;timezone
```

`id` читается как целое число, остальные поля - как строки; координаты затем преобразуются в числа. `timezone` должен содержать обозначение часового пояса, которое понимает Spark. В исходных данных временные поля для перевода в локальное время должны трактоваться как UTC.

## Запуск в подготовленном окружении

Нужны доступ к HDFS и YARN, установленный Spark, совместимые Java/Python и NumPy. Для запуска через Airflow дополнительно нужно настроенное соединение `yarn_spark`.

Все скрипты ожидают **три позиционных аргумента** в одном порядке: `events_path`, `geo_csv_path`, `output_path`.

Пример запуска; пути нужно заменить на свои:

```bash
spark-submit \
  --master yarn \
  --deploy-mode client \
  --conf spark.executor.memory=4g \
  --conf spark.executor.cores=2 \
  --conf spark.driver.memory=2g \
  --conf spark.driver.maxResultSize=20g \
  src/scripts/datamart_users.py \
  '/user/your_user/data/events' \
  '/user/your_user/data/geo.csv' \
  '/user/your_user/analytics/datamart_users'
```

Для двух других витрин замените имя скрипта на `datamart_zones.py` или `datamart_friends_recommendations.py` и задайте отдельный каталог результата. Режим `overwrite` заменяет прежнее содержимое указанного выходного каталога.

## Оркестрация Airflow

| DAG | Cron | Частота |
|---|---|---|
| `load_datamart_users_dag` | `0 1 1 * *` | Первое число месяца, 01:00. |
| `load_datamart_zones_dag` | `0 1 * * 0` | Воскресенье, 01:00. |
| `load_datamart_friends_recommendations_dag` | `0 1 * * *` | Ежедневно, 01:00. |

Параметры Spark одинаковы: `executor.memory=4g`, `executor.cores=2`, `driver.memory=2g`, `driver.maxResultSize=20g`. Это настройки учебной конфигурации, а не результат измеренной оптимизации.
